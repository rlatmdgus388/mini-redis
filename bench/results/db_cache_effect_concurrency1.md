# 실제 DB 캐시 효과 측정 결과

같은 앱을 캐시 끈 채로(매 요청이 PostgreSQL까지), 켠 채로(Mini Redis 먼저) 진짜 HTTP로 돌려 요청 지연을 비교했다. 지연을 흉내 내지 않고 쿼리가 실제로 걸린 시간을 그대로 쟀다. `python -m bench.db_cache_effect`가 이 파일을 다시 만든다.

- 컴퓨터: macOS-27.0.1-arm64-arm-64bit-Mach-O, arm, CPU 10개, Python 3.13.14
- DB: PostgreSQL 16.16 (Debian 16.16-1.pgdg13+1) (Docker 컨테이너, 같은 컴퓨터), users 1,000명 / orders 2,000,000건(user_id 인덱스 없음)
- 아이템(사용자) 100개, 이후 요청 1000개, 동시 요청 1개, 반복 3회 (시드 18)
- 캐시 TTL 60초. 모드마다 프로세스 두 개(Mini Redis, 샘플 앱)를 새로 띄운다. 모든 반복의 행을 그대로 적는다.
- 비-200 응답은 에러 열에 센다. 요청 열은 성공한 요청 수다. DB 호출은 샘플 앱이 DB까지 간 횟수다.
